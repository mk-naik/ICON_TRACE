Where FQC reads the Sun Simulator and EL from

FQC reads these directly, not through the server. SS, EL and FQC share one switch; the server is about four switches away. Routing evidence via the server would make FQC depend on hops the data never needs to cross.
ⓘUnit-2 runs two lines and each has its own Sun Simulator and its own EL, so each is configured separately — two testers can be reconfigured or replaced one at a time, and a column map shared between them would move both at once.
A serial carries no line indicator, so a lookup searches both unless the station’s own line is known. If one share is down and the serial is not on the other, the module is NC, never NA: it may be sitting on the line that could not be read, and NA would send a good module to review.
